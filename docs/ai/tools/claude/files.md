## Scopes

| Scope       | Location                                            | Applies to                       | Shared with team?         |
|-------------|-----------------------------------------------------|----------------------------------|---------------------------|
| **Managed** | System directory / MDM / server-managed             | All users on the machine         | Yes (via IT)              |
| **User**    | `~/.claude/`                                        | You, across all projects         | No                        |
| **Project** | `.claude/` in the repository                        | All collaborators                | Yes (via git)             |
| **Local**   | `.claude/settings.local.json` / `CLAUDE.local.md`  | You, in this project only        | No (gitignored)           |

**Priority** (low → high): User → Project → Local → CLI arguments → Managed

## Key Files in Detail

### Instruction Files (`CLAUDE.md`)

Markdown files that tell Claude how to behave. All are **concatenated** (not replaced)
at session start and injected into the system prompt in this order:

1. Managed `CLAUDE.md` (organization)
2. `~/.claude/CLAUDE.md` (user-global)
3. `CLAUDE.md` from parent directories (monorepo)
4. `./CLAUDE.md` or `./.claude/CLAUDE.md` (project)
5. `./CLAUDE.local.md` (personal / local)

```md
# My Project

## Stack
- Backend: FastAPI + Python 3.12
- Frontend: Next.js 15
- DB: PostgreSQL

## Commands
- Tests: `uv run pytest`
- Lint: `uv run ruff check .`

## Conventions
- Always use type hints in Python
- Commit messages in English using Conventional Commits format
```

**Decision guide:**

| Question                                          | File                    |
|---------------------------------------------------|-------------------------|
| Rule applies to the entire team?                  | `CLAUDE.md` (root)      |
| Rule is personal and project-specific?            | `CLAUDE.local.md`       |
| Rule applies to me across all projects?           | `~/.claude/CLAUDE.md`   |
| Rule is org-wide and must be enforced?            | Managed `CLAUDE.md`     |

> **Tip:** `@path/to/file` imports other files (recursive, max. 5 levels).
> HTML comments (`<!-- ... -->`) are stripped before context injection.

### Rules (`.claude/rules/*.md`)

Rule sets solve the problem of a bloated `CLAUDE.md`. Topic-specific files can be
loaded **always** or **only when relevant** — controlled by the `paths:` field in
the YAML frontmatter.

**Always loaded** (no frontmatter or no `paths:`):
```md
# .claude/rules/code-quality.md

- Every new function requires tests
- Public functions must be documented
```

**Conditionally loaded** (only when matching files are in context):
```md
---
paths:
  - "src/**/*.ts"
  - "*.ts"
---
# .claude/rules/typescript.md

- Strict mode must be enabled
- No `any` types without a comment
```

> ⚠️ Rules without `paths:` are **always** in the prompt — just like another CLAUDE.md.

### Skills (`.claude/skills/<skill-name>/SKILL.md`)

Portable instruction packages for specific workflows. Only the metadata (name,
description) is loaded at startup; the full content is injected **on demand** when invoked.

Invoke via slash command: `/skill-name` or automatically when Claude considers it relevant.

```md
---
name: pull-request-review
description: Step-by-step workflow for reviewing pull requests
---

## PR Review Workflow
1. Check that the PR description explains *why* the change is needed
2. Verify test coverage for all new code paths
3. Look for security issues (injection, auth bypasses, etc.)
```

---

### Agents (`.claude/agents/<agent-name>.md`)

Definitions for specialized subagents. The agent prompt goes in the file body;
configuration is in the YAML frontmatter. Project agents override user-level agents.

```md
---
name: code-reviewer
description: Reviews code changes for quality and standards compliance
tools:
  - Read
  - Bash
model: claude-sonnet-4-6
---

You are a code review specialist. Focus on correctness, security, and readability.
Always check for...
```

Invoke explicitly with: `claude --agent code-reviewer` or via the `agent:` setting.

### Settings (`settings.json`)

JSON files for configuring permissions, hooks, environment variables, and behavior.
Scoped the same way as instruction files.

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)",
      "Read(~/.zshrc)"
    ],
    "deny": [
      "Bash(curl *)",
      "Read(./.env)",
      "Read(./secrets/**)"
    ]
  },
  "env": {
    "NODE_ENV": "development"
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "npm run lint --fix" }
        ]
      }
    ]
  }
}
```

**Files and their purpose:**

| File                           | Scope   | Git?              |
|--------------------------------|---------|-------------------|
| `~/.claude/settings.json`      | User    | No                |
| `.claude/settings.json`        | Project | Yes (committed)   |
| `.claude/settings.local.json`  | Local   | No (gitignored)   |
| `managed-settings.json`        | Managed | Via MDM / IT      |

> Settings are **reloaded live** when the file changes —
> no restart required (except for `model` and `outputStyle`).

### MCP Servers (`.mcp.json` / `~/.claude.json`)

Model Context Protocol — extends Claude Code with external tools and integrations.

```json
{
  "mcpServers": {
    "github": {
      "command": "uvx",
      "args": ["mcp-server-github@latest"],
      "env": { "GITHUB_TOKEN": "ghp_..." },
      "disabled": false,
      "autoApprove": ["list_repos", "get_file"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"]
    }
  }
}
```

**Storage locations by scope:**

| Scope   | File                            | Git?             |
|---------|---------------------------------|------------------|
| User    | `~/.claude.json`                | No               |
| Project | `.mcp.json`                     | Yes (committed)  |
| Local   | `~/.claude.json` (per-project)  | No               |
| Managed | `managed-mcp.json` (system dir) | Via MDM / IT     |

> ⚠️ MCP configuration breaks the global prompt cache — avoid if performance is critical.

### Hooks (in `settings.json`)

Hooks automate actions on specific events during a Claude session. They are **not**
injected into the prompt but execute external code.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "echo 'Tool being executed: $TOOL_NAME'" }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit|MultiEdit",
        "hooks": [
          { "type": "command", "command": "npm run format" }
        ]
      }
    ],
    "ConfigChange": [
      {
        "hooks": [
          { "type": "command", "command": "echo 'Configuration changed'" }
        ]
      }
    ]
  }
}
```

**Available hook events:**

| Event           | When triggered                                  |
|-----------------|-------------------------------------------------|
| `PreToolUse`    | Before any tool execution by Claude             |
| `PostToolUse`   | After any tool execution by Claude              |
| `Stop`          | When Claude finishes its response               |
| `ConfigChange`  | When a settings file is modified                |

### Auto-Memory (`~/.claude/projects/*/memory/`)

Claude Code automatically manages memory files per project. Retrieval is **not**
keyword-based but performed by a parallel Sonnet model that selects up to 5 relevant
files based on the user's prompt.

```
~/.claude/projects/<project-path>/memory/
  MEMORY.md          # Index (always loaded, max. 200 lines / 25 KB)
  auth.md            # Topic: authentication logic
  database.md        # Topic: database schema & migrations
  api-design.md      # Topic: API conventions
```

> Files older than 1 day automatically receive a warning:
> *"This memory is X days old — please verify it is still valid"*

## How Claude Code Builds the Context

The system prompt consists of two sections (relevant for token efficiency):

```
┌──────────────────────────────────────────────────────────┐
│  STATIC SECTION  (global cache — identical for all       │
│  Claude Code users worldwide)                            │
│                                                          │
│  1. Identity & introduction                              │
│  2. Behavioral rules                                     │
│  3. Task execution instructions                          │
│  4. Tool usage instructions                              │
│  5. Tone & style                                         │
│                                                          │
├──────────────────────────────────────────────────────────┤
│        === DYNAMIC BOUNDARY ===                          │
├──────────────────────────────────────────────────────────┤
│  DYNAMIC SECTION  (session-specific)                     │
│                                                          │
│  6.  Session guidance                                    │
│  7.  Instructions: CLAUDE.md files (concatenated)        │
│  8.  Environment info (date, OS, model, session ID)      │
│  9.  Language preference                                 │
│  10. MCP instructions (when servers are configured)      │
│  11. Output style                                        │
│                                                          │
│  + MEMORY.md (always, max. 200 lines)                   │
│  + Up to 5 memory files (selected by relevance query)    │
└──────────────────────────────────────────────────────────┘
```

**Practical implications:**

| Problem                              | Solution                                            |
|--------------------------------------|-----------------------------------------------------|
| CLAUDE.md is getting too long        | Move content to `rules/` with a `paths:` condition  |
| All rules always in the prompt       | Add `paths:` for conditional loading                |
| MCP breaks the cache                 | Configure MCP only where necessary                  |
| Skill content consuming tokens       | Skills have two-phase loading — not a problem       |
| Memory becoming stale                | Warning appears automatically after > 1 day         |
